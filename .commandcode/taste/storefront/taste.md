# storefront

# product details / variants
- Storefront product detail pages must expose product variants with an easy-to-use picker ("great ux"): color axes rendered as swatches, size axes as pill/button selectors, and selection validated (every axis chosen) before the item can be added to the cart, resolving price/stock from the chosen SKU ("if the product has variants load them properly if it has colors, sizes and let customer choose easily (great ux)"). Confidence: 0.7
- Variant loading must be data-driven and edge-case safe: build the picker axes from the variant attribute data itself ("load variants not separately colors or sizes, load variants and what variants attribute has like color or size"), and filter each axis's options down to only those that actually appear in a concrete purchasable SKU with stock, never show declared-but-unused options (the user flagged exactly this bug: "it is loading all 3 colors but variant has 2 types 2 colors 1 size used"). Confidence: 0.75
- Variant selection on the product detail page must update the displayed price to the offer-applied per-variant price while the product has an active offer; a product that has an offer but shows no price change when switching variants is reported as a bug ("the variant choosing working but the price is not updated when it product has offer"). Confidence: 0.6
- When the selected variant has its own images, the product gallery must show those variant images; otherwise it falls back to the product's main images ("when updating variants and when it has images it doesn't show those images"). Confidence: 0.65
- Variant-enabled products must default-select the first variant for add-to-cart / buy actions from the /products listing page, so the customer does not have to open the detail page to pick a variant; this means NO warning toast and NO redirect to the product page, choose the first in-stock variant automatically and send it along with the add-to-cart request ("I said add to cart don't warn the user add and choose if the product has variant, choose first variant automatically and send it along with the request"). Confidence: 0.8
- When a product has an active offer, the product detail page must visibly highlight the offer's cut-down (strikethrough) price and discount percentage so the customer can see what they're getting ("make sure it also highlights the offer price cut down amount, so user can see visually what he is getting"); when a variant is selected, the strikethrough must be that variant's own pre-offer base price (not the product base price) so the displayed savings are per-variant accurate. Confidence: 0.75

# cart
- The public cart must include a visible "Clear Cart" button once one or more items are in the cart, so the whole cart can be emptied in one click ("On cart when one or more items are added add a clear cart button to easily clear out the cart"). Confidence: 0.7
- Cart quantity mutations must be stock-aware: cap quantities at the actual available stock, the selected variant's stock for variant lines, else the product's own stock, and when a user tries to cross that limit, surface a clear, friendly UI message (either a toaster or an inline message near the section), never a silent no-op or unchecked merge ("make sure it keep track of how much the actual product stock or if variant product selecting it stock is, if it crosses the limit it should beautiful show ui message to use user, using toaster or ui message near the section"). Fresh evidence: reiterated the same requirement, "add ui message by sonner or on section in checkout page", and flagged that the message was working on /products but still missing on /product-details. Confidence: 0.85

- The checkout order summary must show offer savings and coupon savings as separate, visible discount lines, "Offer Discount" plus "Discount (coupon code)", each rendered only when it actually applies; showing only the coupon discount while offer savings are silently baked into the subtotal is reported as a bug ("order summary section is not showing offer discount but only coupon discount make sure show necessary one when they are available and applied").
