# shadcn
- Always use shadcn components instead of native HTML elements (explicitly: "must use shadcn buil, n calendars instead raw calender"). Confidence: 0.9
- Date pickers/calendars must use the shadcn Calendar + Popover components (single or range mode) , never native `<input type="date">`/`datetime-local` or raw text inputs (coupon create/update forms, the profile Date of Birth field, the settings limited-offer Ends At field, and the product offer start/end date fields in the product create/update forms were all converted; profile, settings, and product offer dates were explicitly requested to use the shadcn calendar, "offer section date convert to shadcn calender"). Confidence: 0.97
- Date fields can also combine the shadcn Calendar with a manual free-typing input when the user asks to keep both: the Date of Birth field on the admin & customer profile pages was requested with month/year/day dropdowns for easy selection (`captionLayout="dropdown"` + `startMonth`/`endMonth` bounds) AND a fast-typing text input kept in two-way sync (a typed valid date updates the calendar selection; a picked date fills the input), plus inline validation for malformed/future/implausibly-old dates ("update the Date of Birth calendar to month, year, day easily selectable also user can manually input by typing (fast type), so keep both features"). Confidence: 0.8
- Avoid nested anchors (`<a>` inside `<a>`), which cause hydration errors: shadcn/Base UI components that default to an `<a>` tag (e.g., `SidebarMenuSubButton` via `useRender`) must not be wrapped in a Next `<Link>` , instead pass `render={<Link href={...} />}` so the component renders as the Link anchor itself (the same pattern as `SidebarMenuButton`). Confidence: 0.6
- Select controls must look shadcn-styled, never raw default-browser styling ("Make sure all select options are used from shadcn style, no default inputs, the calendar, month and year select looks default browser theme"). For the calendar's month/year caption dropdowns, the working approach is the official shadcn pattern: a native `<select>` styled with shadcn theme classes — themed trigger via the calendar's `dropdown_root`/`dropdown`/`caption_label` classNames (border, bg-popover, radius, focus ring) — NOT a Base UI `Select` override. Overriding `MonthsDropdown`/`YearsDropdown` with the popover-based shadcn Select broke the calendar: the nested select's portaled list triggered the outer popover's outside-press dismissal, so the month/year options never opened ("Month and Year select option is not working, not opening the choosing option."). Offered the trade-off, the user chose the styled native select (reliable; OS-drawn option list when opened) over the fully-themed select that breaks interaction. Confidence: 0.8
- Prefers the reliable standard implementation over a more fully-themed custom one when the two conflict: when a customized control breaks core interaction (e.g., the Base UI Select nested inside the calendar popover), the user accepts a themed-but-native fallback that actually works over a pixel-perfect one that doesn't (explicitly chose "Styled native select" over "Keep Base UI Select, stop outer dismiss" for the calendar month/year dropdowns). Confidence: 0.7
